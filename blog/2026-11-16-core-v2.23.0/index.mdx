Zaparoo Core v2.23.0 adds experimental builds for nine more systems. Knulli, ROCKNIX, AmberELEC, ArkOS, muOS, Lakka, RetroPie, and Armada each get their own build and install guide, and Recalbox goes from shell scripts only to launching games through EmulationStation. Most of them are firmware for retro handhelds.

{/* truncate */}

Windows no longer needs a frontend to launch emulator games. Core finds about 60 standalone emulators and RetroArch on its own, and Playnite joins LaunchBox and RetroBat as a launcher with its own extension for writing tags.

**The highlights:**

- **[New platforms](#new-platforms)**: Knulli, ROCKNIX, AmberELEC, ArkOS, muOS, Lakka, RetroPie, Armada, and Recalbox
- **[Windows emulators](#windows)**: about 60 standalone emulators, RetroArch, and Playnite
- **[USB serial adapters](#usb-serial-adapters)**: CH340 and PL2303 readers on systems with no kernel driver for them
- **[Linux emulators](#linux-emulators)**: DuckStation, PPSSPP, and melonDS games are indexed, and GroovyMAME has its own launcher
- **[Playlists](#playlists)**: a prompt when a playlist pauses or a game fails to start

Core will let you know about this release in the Inbox. On MiSTer, Update All installs it, and on Batocera the package manager does. Everywhere else it installs itself if you have turned on [automatic installs](/docs/core/updates/#automatic-installs), or you can download it above.

## Before you update

- **Update the media database** to pick up the new systems, DuckStation, PPSSPP, and melonDS games on Linux, and system folders whose name differs only in case, such as `SNES`.
- **Recalbox has its own build now.** If you set up the Linux build by hand, install again with the steps on the [Recalbox page](/docs/platforms/recalbox/). Config, data, and logs move to `/recalbox/share/system/zaparoo`.
- **Core advertises itself over Bluetooth LE**, ready for Bluetooth support in a later Zaparoo App release. It's on by default on Linux-based platforms and Windows with a Bluetooth adapter, and clients still have to pair with Core's PIN. Turn it off with [`[service.ble]`](/docs/core/config/service/#serviceble).
- **Windows emulators need `index_root`.** Core only scans for standalone emulator and RetroArch games under the folders set in [`launchers.index_root`](/docs/core/config/launchers/#index_root).

## New platforms

**Applies to:** the platforms below. All of them are experimental for now, so expect missing features and rough edges.

| Platform | Builds | Launches through |
| -------- | ------ | ---------------- |
| [Knulli](/docs/platforms/knulli/) | ARM, ARM64 | EmulationStation |
| [ROCKNIX](/docs/platforms/rocknix/) | x86-64, ARM64 | EmulationStation |
| [AmberELEC](/docs/platforms/amberelec/) | ARM64 | EmulationStation |
| [ArkOS](/docs/platforms/arkos/) and dArkOS | ARM64 | EmulationStation's own launch commands |
| [muOS](/docs/platforms/muos/) | ARM64 | muOS's content loader |
| [Lakka](/docs/platforms/lakka/) | x86-64, ARM, ARM64 | RetroArch, including RetroArch playlists |
| [RetroPie](/docs/platforms/retropie/) | x86-64, ARM, ARM64 | RetroPie's `runcommand` |
| [Recalbox](/docs/platforms/recalbox/) | x86-64, ARM, ARM64 | EmulationStation |
| [Armada](/docs/platforms/armada/) | ARM64 | Steam, Heroic, Moonlight, and standalone emulators |

Each one installs with the same command over SSH or a terminal:

```bash
curl -fsSL https://zaparoo.org/install.sh | sh
```

Core adds a launcher for each system the OS has set up and indexes its ROM folders, so cards written on Batocera or MiSTer work the same way. Lakka gets the full set of RetroArch controls, such as save states and disc swapping, and ArkOS gets them once RetroArch network commands are turned on. On the others, stopping a game is the only control for now.

A few need an extra step, all covered on their pages: muOS only starts Core on boot with **User Init Scripts** turned on, RetroPie installs as the `pi` user and needs to boot to EmulationStation on the console, and older AmberELEC releases need the prerelease or a manual install. Remote clients on all of these need to [pair](/docs/core/config/service/#encryption) with a PIN before they can connect.

## Windows

**Applies to:** Windows.

Until now, Windows launched emulator games only through a frontend like LaunchBox or RetroBat. Core now finds [standalone emulators](/docs/platforms/windows/launchers/#standalone-emulators) itself: about 60 of them, from MAME, Dolphin, and PCSX2 to DuckStation, Cemu, Xenia, and VICE. It looks in the places emulators usually end up, such as Program Files, Scoop and winget installs, `PATH`, and `Emulators` folders, and you can point it at one with `install_dir`. Games are indexed from ES-DE-style folders like `snes` and `psx` under your `index_root`.

[RetroArch](/docs/platforms/windows/launchers/#retroarch) works the same way, including the Steam version, using the cores you have installed. Save states, the menu, pause, and disc swapping all work, and Core turns on RetroArch's network commands with a separate config file rather than editing yours.

[Playnite](/docs/platforms/windows/launchers/#playnite) is a new launcher. With the Zaparoo extension installed, Core indexes your Playnite library and launches games through Playnite, so your Playnite emulator setups still apply. Games you start from Playnite itself show as playing in Zaparoo too. Right-click a game in Playnite and choose **Write to Zaparoo tag** to write a card for it. The `playnite` [scraper](/docs/features/scraping/#playnite) imports Playnite's metadata and covers.

## USB serial adapters

**Applies to:** Linux-based platforms.

Some systems ship without the kernel driver for CH340 or PL2303 USB serial chips, which most PN532 USB readers use. Core now drives those chips itself, so a [PN532 USB](/docs/readers/nfc/pn532-usb/) reader is still detected on those systems, a few seconds after you plug it in. Simple Serial readers and RS-232 barcode scanners can use it with a [`usbserial:` path](/docs/readers/simple-serial/#adapters-without-a-kernel-driver).

## Linux emulators

**Applies to:** Linux, SteamOS, Bazzite, ChimeraOS, and Armada.

- **DuckStation, PPSSPP, and melonDS games are indexed** from the `psx`, `psp`, and `nds` folders, instead of launching only from a file path.
- **GroovyMAME has its own launcher**, used ahead of MAME when both are installed.
- **MAME keeps the ROM paths in your `mame.ini`**, so BIOS and parent sets in other folders load, and `window 1` is respected. It's also found as `mame64`, and the `mame` folder is indexed as well as `arcade`.
- **ARMSX2 is picked up** by the PCSX2 launcher.

See [standalone emulators](/docs/platforms/linux/launchers/#standalone-emulators) for folders and file types.

## Playlists

**Applies to:** All Core platforms.

When you quit a game within 30 seconds of the playlist starting it, the playlist still pauses, but it now asks whether to play the next item or stop. A game that never starts, such as one stuck on a missing BIOS, no longer counts as you quitting it. The playlist pauses on it with a **Couldn't start** prompt to try again, skip, or stop. See [moving to the next item](/docs/features/playlists/#moving-to-the-next-item-on-its-own).

Batocera can't show pickers, so it shows the countdown, the pause, and the failure as EmulationStation notices. Scan the card again to continue a paused playlist.

A new scan that launches something also ends a [`**delay`](/docs/zapscript/utilities/#delay) still waiting from an earlier scan.

## Library

- **Four new systems:** Exelvision EXL 100 (`EXL100`), Philips P2000T (`P2000T`), Philips VG5000 (`VG5000`), and Z-machine (`ZMachine`) for Infocom games. Recalbox indexes all four and RetroPie indexes Z-machine games. See [systems](/docs/features/systems/).
- **System folders are found whatever their case**, so `roms/SNES` is indexed as SNES on Linux systems. A folder with the exact name still wins when both exist.

## Fixes

- **The Zaparoo entry in Batocera's game menu now shows up**, so **Write an NFC tag for this game** works from EmulationStation.
- **Notices from remote URL launches** show `Insert disk 2` instead of `Insert%20disk%202`.
- **Manuals copied from a Mac open again.** The scraper skipped over the hidden `._` files macOS leaves on USB drives. Updating Core is enough; the next scrape picks up the real files.
- **On MiSTer, a deck's exit countdown waits until it's on screen** before counting down.
- **Resuming a shuffled playlist plays every item**, starting with the one you left off on.
- **On MiSTer, `**stop` from the menu no longer reloads it**, which could drop a game scanned straight after.
- **`**playlist.stop` with no playlist active** does nothing instead of failing, so the rest of the script runs.

## API changes

- The API is served over Bluetooth LE, with pairing through `pair.start` and `pair.finish`. `settings` and `settings.update` have `bleEnabled`.
- `device.endpoints` lists the other addresses a client can reach this Core on, so a client connected over Bluetooth can move to the network.
- WebSocket clients can send encrypted frames as binary messages, without the JSON wrapper.
- `ui.shown` lets a client report that it has put a UI event on screen.
- `/health` returns plain `OK` unless the request asks for JSON.

See the [API reference](/docs/core/api/methods/) for details.
