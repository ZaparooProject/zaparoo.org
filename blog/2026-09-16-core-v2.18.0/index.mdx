Zaparoo Core v2.18.0 is now available. Windows gets real keyboard and gamepad input and a PinUP Popper launcher for virtual pinball cabinets. Tapping the card for the game you are already playing no longer restarts it. You can group systems into categories of your own, hide entries from the library, and multi-disc games show as one item.

{/* truncate */}

MiSTer gains CDTV and DVD Player launchers, arcade artwork from Skraper-style gamelists, and a fix for shared folders like Game Boy and Game Boy Color mixing up each other's artwork. RetroArch launchers can swap discs from a card. Browsing a folder with thousands of games, or searching a big library, no longer stalls on every page.

Thank you to [Trey Turner](https://github.com/treyturner) for adding support for PN532Killer readers.

**The highlights:**

- **[Windows input](#windows)**: `input.keyboard` works, and a virtual gamepad is available with the ViGEmBus driver
- **[PinUP Popper](#pinup-popper)**: index, launch, and stop virtual pinball tables on Windows, with Popper's own artwork
- **[Tap mode](#readers-and-scanning)**: scanning the running game leaves it alone, unless you turn `allow_relaunch` back on
- **[Custom categories](#custom-categories)**: a kids shelf or favorites group of systems, shown in the App and Frontend
- **[Library](#library-and-scraping)**: hidden entries, multi-disc sets as one game, folder artwork, and fast pages in huge folders
- **[MiSTer](#mister)**: CDTV and DVD Player launchers, arcade gamelists by set name, shared-folder artwork fixed
- **[RetroArch disc controls](#launchers)**: open the tray and switch discs from a control card

## Before you update

- **Windows requires paired clients now.** Encryption is on by default on Windows, including existing installs unless `config.toml` sets `encryption = false`. Pair the App and any other remote client after updating, using **Pair Device...** in the tray menu. See [client security](/docs/platforms/windows/#client-security).
- **Tapping the card for the running game no longer restarts it.** This applies in tap mode to any card, mapping, or script that resolves to the same game. If you relied on a re-tap to restart, set [`allow_relaunch = true`](/docs/core/config/readers/#allow_relaunch) under `[readers.scan]`.
- **Windows gamepad input is off until you turn it on.** Run the installer and tick the ViGEmBus driver task, then set `gamepad_enabled = true` under `[input]`. See [Windows input](/docs/platforms/windows/#input).
- **Virtual systems use `categories` now.** Custom launchers with `kind = "virtual_system"` take a `categories` list. The old `category` key still works.
- **Update the media database, then scrape again.** Multi-disc sets, folder artwork, and hidden entries need a fresh index. On MiSTer, re-run your scrapers so shared-folder systems and arcade games pick up the matching fixes below.
- **CDTV on MiSTer needs a saved preset.** See [Commodore CDTV](/docs/platforms/mister/launchers/#commodore-cdtv).

## Windows

- **Keyboard input works.** `input.keyboard`, `input.text`, the coin commands, and keyboard macros did nothing on Windows and reported success. They now send keys to the active window from Core's own session, with no administrator rights or helper process. Two limits apply: input cannot reach a window running as administrator, or the lock screen, and the character a key produces depends on the active keyboard layout. See [Windows input](/docs/platforms/windows/#input).
- **A virtual gamepad, with a driver.** Windows has no built-in way to fake a controller, so `input.gamepad` uses [ViGEmBus](https://github.com/nefarius/ViGEmBus), the driver DS4Windows and Parsec use. The installer offers it as an unticked option (it is a kernel-mode driver, and there is no ARM64 build). Gamepad support stays off by default because a surprise controller shifts every real one's slot in games; turn it on with [`gamepad_enabled`](/docs/core/config/media/#gamepad_enabled). With the setting on and no driver, the command says the driver is missing instead of pretending. Uninstalling Zaparoo leaves the driver in place for other software.
- **Encryption on by default.** Remote clients on Windows must pair, matching Linux and SteamOS. A config that already sets `encryption = false` is kept.
- **The App's remote keyboard follows the key lists.** Keyboard input sent through the API by a paired member client now goes through the same [`[zapscript.input]`](/docs/core/config/#zapscriptinput) allow and block lists as a scanned card, so the default desktop block on `{alt+f4}` and `{ctrl+alt+delete}` covers both. Admins and localhost are exempt.
- **Filesystem roots show up in browse.** Directories like `C:/roms/` were missing from the root listing and counted as empty, and play history entries launched with a Windows path came back without tags.

### PinUP Popper

**Applies to:** Windows.

Core now launches virtual pinball tables through [PinUP Popper](/docs/platforms/windows/launchers/#pinup-popper). It finds the PinUP System folder through Popper's registry entry, indexes every table in Popper's database under the `Pinball` system, and asks Popper to start and stop tables, so Popper's launch scripts, PuP-Packs, and DOF setup carry on working. Visual Pinball, Future Pinball, Pinball FX, Pinball M, Zaccaria, and Pro Pinball tables are all tracked as running games, so hold mode, playtime limits, and scanning another table behave as they do everywhere else.

A new `pinup-popper` scraper imports the year, manufacturer, player count, notes, and wheel, playfield, backglass, and flyer images from Popper's own library. It runs on its own after each media database update and only fills in tables with no metadata yet, so edits you make in Popper reach Zaparoo without a manual scrape. See [pinup-popper](/docs/features/scraping/#pinup-popper).

## Readers and scanning

- **Tap mode leaves the running game alone.** Scanning a card in tap mode that resolves to the game already playing is now a successful no-op, whether it is the same card, a different card, a mapping, or a script that lands on the same file. Playtime, playlists, and hooks are untouched, and any other commands on the card still run. A random pick that lands on the running game is also skipped, while a different result launches. Set [`allow_relaunch = true`](/docs/core/config/readers/#allow_relaunch) to get restart-on-tap back. Hold mode, API launches, and playlists are unchanged, and [launch guard](/docs/features/play-controls/#launch-guard) no longer asks you to confirm a tap that would not change anything.
- **PN532Killer readers are supported.** In UART mode they are detected like any [PN532 USB](/docs/readers/nfc/pn532-usb/) reader, and the Linux hardware installer's udev rule covers them. Thanks to Trey Turner.
- **Unplugged readers go quietly.** PN532, barcode, Simple Serial, and TTY2OLED readers over USB were removed and re-announced every second after being unplugged, because their ID changed once the port was gone. A reader now keeps its ID for its lifetime.
- **Auto-detect stops re-probing devices that never answer.** A USB serial device that is not a PN532 was probed on every pass. Probe results now come from the PN532 library itself, so the summary in the log lists the ports that were actually tried.
- **Hold mode ownership survives a fast relaunch.** Relaunching a software token before the previous exit finished could let the old cleanup clear the new token's owner.

## Library and scraping

- **Multi-disc games are one game.** A folder of loose disc images that all share a title, in `.cue`, `.chd`, `.iso`, `.bin`, `.img`, or `.pbp`, is now shown and launched as one item, the way a folder with an `.m3u` already was. You can still open the folder to pick a disc.
- **Folders can have artwork.** The `media-folder` scraper now picks up an image named after any folder, at the mirrored path or the flat name under `media/`, and clients that show folder art get it through the usual image lookup. See [media-folder](/docs/features/scraping/#media-folder).
- **Hide entries you do not want to see.** A new `user:hidden` tag, set the same way as favorites, removes an entry from browse, search, counts, the letter index, and random picks. It still launches from a card, a script, a playlist, or an explicit API call, and favorites and history keep it. Clients can ask for hidden entries back to manage them. There is no button for this in the App or Frontend yet; API clients can use it now.
- **Scrape one game or one folder.** A scrape can be scoped to a single media entry, a file, or a folder, and the scope survives a restart. Frontend already exposes this on a game's options menu.
- **Scrapes resume and queue.** A scrape interrupted by a restart carries on where it stopped, cancelling is durable, and scrapers that run after an index (currently PinUP Popper) queue behind optimization instead of colliding with it.
- **Huge folders page quickly.** A folder with thousands of games, or a sorted search across a big library, was doing far more work than one page needs: caches never hit, the cursor scanned from the top of the folder on every page, and a bad planner statistic drove whole-library scans. Each page now costs a page, the indexes involved are checked and repaired at startup, and a broad sorted search that used to time out now just returns.
- **Ranked title suggestions for clients.** A new `media.lookup.candidates` method returns up to five likely titles for an approximate name in one system, for clients that want to confirm a match before launching.
- **Manuals over the API.** `media.asset` delivers an indexed PDF manual in chunks over the WebSocket, so a client can show manuals without a file share.

## Custom categories

**Applies to:** All Core platforms.

Systems have always sat in fixed categories: Console, Handheld, Computer, Arcade, and Other. You can now declare your own in `config.toml` and put any systems in them:

```toml
[[systems.category]]
name = "Kids"
systems = ["NES", "SNES", "Genesis"]
```

A system stays in its built-in category and also appears under every custom one that names it. The App and Frontend show custom categories alongside the built-in ones. Custom launchers that add a virtual system can use these names too, through a `categories` list that replaces the single `category` key. See [`systems.category`](/docs/core/config/launchers/#systemscategory).

Config handling got sturdier in the same change: a bad category entry is logged and skipped rather than stopping Core, a settings change from a client is refused when `config.toml` cannot be loaded instead of overwriting it, inline custom launchers and mappings are written back on save instead of dropped, and a custom launcher file with an unknown field is skipped with a warning that names the field. Config files, the auth file, and the MiSTer, RetroArch, and profile files Core writes are all saved atomically now, so an interrupted write cannot leave a half-written file behind.

## MiSTer

- **Commodore CDTV.** CD images in a `CDTV` folder launch through the Minimig core using a saved preset. Save a CDTV configuration as `CDTV` in the core first. See [Commodore CDTV](/docs/platforms/mister/launchers/#commodore-cdtv).
- **DVD Player.** `.iso` images in a `DVD` folder launch through the FPGA DVD core, with a `HybridDVDPlayer` alternate launcher for the hybrid core.
- **Kitrinx NGPC is preferred.** Neo Geo Pocket Color games use the Kitrinx core when it is installed and fall back to Jotego's otherwise. A token that names a launcher explicitly is honored as written.
- **Arcade gamelists match by set name.** A `gamelist.xml` from Skraper or a similar tool lists arcade games as `pacman.zip`, which never matched an `.mra`. The scraper now reads the set name inside each `.mra` and matches on that, artwork included, so a Skraper arcade pack works through a custom bundle. Hardware classifications like `CPS1` can be scraped from a bundle too. See [MiSTer arcade gamelists](/docs/features/scraping/#mister-arcade-gamelists).
- **Shared folders keep their artwork straight.** Game Boy and Game Boy Color share `GAMEBOY`, and nine other folders are shared the same way. A gamelist entry for one system's file could be applied to the other system's game with the same name. Each system now only matches files it would index. Nested ROM roots pick the most specific root for artwork, and games running on alternate cores like `RA_GBC` are tracked under the right system.
- **ScummVM games get metadata.** The scraper matches ScummVM entries, and a `gamelist.xml` that starts with a byte-order mark is accepted.
- **Two games behind the same MGL.** Launching a second game through `.LASTLAUNCH.mgl` was identified as the same game as the first, so active media never updated. Games are now identified by the file the MGL loads.

## Launchers

- **RetroArch disc controls.** The built-in RetroArch launchers on Linux and SteamOS, including EmuDeck, accept `toggle_tray`, `next`, and `previous` [control actions](/docs/features/launchers/#launcher-controls), so a control card can swap discs in a multi-disc game without restarting it. RetroArch does not report whether the swap worked, so these are best effort, and the disc set has to be loaded already.
- **Steam games that are not installed open their page.** Scanning a `steam://` token for a game that is not installed used to hand it to Steam anyway. Core now checks the install first and opens the game's Steam details page instead, without stopping the game you are playing. Non-Steam shortcuts and an explicit `action` are unchanged.
- **SteamOS launches can be hosted by a frontend.** In Gaming Mode, Core starts emulators through the Zaparoo Runtime shortcut. A frontend that Steam launched, like a coming release of Zaparoo Frontend, can now register to run the emulator itself, so you do not end up with two Steam apps open for one game. Without a frontend, nothing changes.
- **A missing gamepad no longer stops the service.** On every platform with virtual input, a gamepad that cannot be created is reported by the commands that need it rather than preventing Core from starting.

## Service and diagnostics

- **Crashes leave evidence.** A crash is written to `core.crash.log` in Core's data directory, kept as `core.crash.previous.log` across the next healthy start, and included in log bundles. If [error reporting](/docs/core/config/#error_reporting) is on, one sanitized report is sent on the next start; the raw crash text stays on the device.
- **Stale PID files recover.** A service start that finds a PID file pointing at some unrelated process now cleans it up and starts, without signalling that process. Stop and restart still refuse to touch a PID that is not Core's.
- **Long WebSocket sessions are not cut off.** The WebSocket route carried a 30 second request timeout, which wrote an error header onto the live connection and a warning to stderr once a session got older than that.
- **Fewer false alarms in error reports.** Expected outcomes, like a refused script while another is running, an unsupported control action, a missing writable reader, or a missing file, are no longer reported as errors, and `execute` failures no longer include the command line or its output.
- **Smaller downloads.** Release binaries are noticeably smaller with nothing removed.

## API changes

- `systems` and `media.search` results carry a `categories` array; `category` is kept for older clients and always equals the first entry.
- `media.tags.update` accepts `user:hidden` alongside `user:favorite`. `media.browse`, `media.search`, and system counts take `includeHidden`, and a `media.visibility` notification announces changes.
- `media.browse` marks collapsed disc sets and folders with artwork through `hasCover`, and `media.image` accepts a directory.
- `media.scrape` takes an optional scope: a media ID, an exact file, or a folder.
- New `media.lookup.candidates` and `media.asset` methods, described above.

See the [API reference](/docs/core/api/methods/) for details.
